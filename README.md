# ELDEN RING ARCHIVE

본편과 **Shadow of the Erdtree**만을 다루는 개인용 엘든 링 위키·SQLite 데이터베이스·플레이 기록 도구입니다. Nightreign(엘든 링 밤의 통치자) 콘텐츠와 전용 시스템은 포함하지 않습니다. 어두운 올리브 배경과 금빛 포인트, 최소한의 장식, 한국어 UI로 구성했습니다. 공식 사이트나 위키의 화면을 복제하지 않았습니다.

## 실행

Node.js **22 LTS 또는 24 LTS**와 npm이 필요합니다. Docker, 계정, 외부 DB, API 키는 필요하지 않습니다.

```bash
npm install
npm run dev
```

개인 PC의 브라우저에서 `http://127.0.0.1:3000`을 엽니다. 이 주소는 **내 PC 실행용**이며 클라우드 웹 미리보기 링크가 아닙니다. 첫 설치의 `postinstall`이 Prisma Client 생성, SQLite 초기화, 데이터 입력을 자동 실행합니다. 실행 명령은 프로젝트 루트에서 사용하세요. Windows에서도 같은 명령을 사용합니다.

SQLite 네이티브 드라이버의 사전 빌드가 없는 플랫폼에서는 C/C++ 빌드 도구와 Python이 필요할 수 있습니다. 클라우드 Node 24 환경에서는 시스템 GCC/Python으로 드라이버를 빌드해 검증했습니다. 패키지 TLS·체크섬 검증은 끄지 않습니다.

프로덕션 실행:

```bash
npm run build
npm start
```

기본 서버는 `127.0.0.1`에만 바인딩됩니다. 복잡한 로그인은 없으며 관리자 쓰기 API는 loopback Host와 같은 Origin만 허용합니다. 인터넷 공개용으로 배포하려면 별도의 인증 설계가 필요합니다.

## 실제 구현된 기능

- 메인 아카이브, 스크롤 가능한 카테고리 사이드바, 모바일 메뉴
- 한국어·영어·별칭·획득 위치·태그 부분 검색, 자동완성, 키보드 선택, 페이지 나누기
- 전체/본편/DLC 필터, 카테고리 필터, 지역의 동굴·갱도·지하묘지·봉인감옥 등 세부 필터
- 무기·보스·NPC·지역·탈리스만 DB 및 방어구·마술·기도·전회·영체·아이템의 공통 상세 문서
- 기본 공격력·가드·요구 스탯·보정·방어구 경감률·효과 등의 구조화 데이터 표시
- 양방향 관계 링크: 획득 장소, 보스, 드랍, 지역, NPC, 퀘스트, 교환 보상 등
- 문서별 즐겨찾기, 카테고리별 즐겨찾기 목록
- 플레이 체크리스트와 현재 필터의 수집 문서 기준 진행률
- 라니·밀리센트·알렉산더 퀘스트 단계, 위치·NPC·선행 조건·다음 단계·주의사항·완료 체크
- 스포일러 숨김 토글, 문서별 열람, 퀘스트 결말/보상/경유지와 NPC 이동/선택 결과 보호
- 개인 메모, 빌드 노트(레벨·8종 능력치·장비·마법 선택·여러 빌드 저장)
- 진행도·즐겨찾기·메모 JSON 백업/복원, 빌드 JSON 내보내기
- `/admin`: 추가·수정·삭제, 태그·별칭·본편/DLC·검증 상태·출처·관계 관리, 문서 JSON 가져오기/내보내기
- 퀘스트 단계·강화 단계·이미지 출처 URL은 관리자 문서 JSON에서 고급 편집 가능
- 모든 수집/관리자 입력의 대상 외 게임 검사와 SQLite 범위 제약

이미지는 출처·라이선스가 불명확하므로 자동 다운로드하지 않았습니다. UI는 직접 작성한 SVG 장식과 카테고리 아이콘을 사용합니다. 이미지 URL과 출처 필드는 준비되어 있고 링크로 확인할 수 있습니다.

### 출처와 검증 수준

1. [deliton/eldenring-api](https://github.com/deliton/eldenring-api/tree/1d2626ceda5eb8c08997e345e303344a64edc106): **2022-05-31** 커밋 `1d2626ceda5eb8c08997e345e303344a64edc106`의 공개 JSON 12종에서 정형 사실 필드를 실제 수집했습니다. 원본 2,254개 레코드를 정제하고, 알려진 미출시·미사용 항목을 제외했습니다. 같은 이름의 여러 조우/중복 레코드가 남아 있어 후속 정리가 필요합니다.
2. DLC와 주요 본편 지역·진행 정보는 직접 작성한 간결한 사실 목록입니다. 문서별 [Elden Ring Wiki](https://eldenring.wiki.gg/) 링크는 **후속 검토용**입니다. 링크 존재/내용의 확인 또는 독립 검증을 완료한 것으로 표시하지 않습니다.
3. [Bandai Namco 공식 자료](https://en.bandainamcoent.eu/elden-ring/elden-ring)를 먼저 참고하고, 게임 내 수치와 독립 위키 자료를 비교할 수 있도록 출처 목록을 제공합니다. 이번 클라우드의 현재 네트워크 정책에서 공식 사이트·위키 요청은 403으로 제한되어 교차 확인하지 못했습니다.
4. [ERDB](https://github.com/EldenRingDatabase/erdb)의 게임 데이터 추출 방식에 관한 문서를 확인했습니다. ERDB의 게임 수치를 이번 DB에 가져오거나 검증 자료로 사용하지 않았습니다.

원본의 긴 설명문·대사·이미지는 저장하지 않습니다. 짧은 효과, 위치, 요구 능력치 등 사실 중심 필드만 보관합니다. 수집 코드가 위키를 무단 크롤링하거나 접근 제한을 우회하지 않습니다.

모든 초기 문서는 `verification_status: needs_review`입니다. 수치가 최신 패치와 다를 수 있으며 `???` 값은 미등록으로 처리합니다. 이름을 번역했다고 수치까지 검증된 것은 아닙니다. `verified`로 저장하려면 출처 URL과 직접 확인한 날짜를 반드시 등록해야 합니다. 아직 실행하지 않은 교차 검증을 완료한 것처럼 표시하지 마세요.

Next.js 16 App Router, TypeScript, React 19, Tailwind CSS 4, Prisma 6, SQLite를 사용합니다. Prisma ORM의 공식 JavaScript 엔진과 `@prisma/adapter-better-sqlite3`를 사용해 별도의 Rust 엔진 다운로드가 필요하지 않습니다. CLI의 JS adapter 설정은 Prisma 6의 `experimental.adapter` 옵션을 사용하며 버전이 고정되어 있습니다. Node 24와 호환되는 `better-sqlite3` 12.11.1을 overrides로 고정했습니다. 실제 설치·DB 처리·빌드·웹 요청으로 조합을 검증했습니다.

## DB 구조

| 모델 | 목적 |
|---|---|
| `Entry` | 공통 문서, 한/영 이름, 분류, `content_type`, 검증 상태, 태그·별칭·구조화 수치, 검색 색인, 스포일러 |
| `Relation` | from/to 외래키 + 관계명. 역방향 링크는 조회 시 자동 생성 |
| `EntrySource` | 문서별 출처 URL, 메모, 실제 확인 시각 |
| `QuestStep` | 순서, 위치/NPC ID, 필요 아이템 ID 목록, 선행 조건, 다음 단계, 실패/주의 조건, 스포일러 |
| `WeaponUpgrade` | 무기·강화 단계·변질별 공격력과 보정. 초기 단계별 데이터는 미수집 |
| `SeedRegistry` | 기존 입력/삭제 ID를 기록해 재설치 시 사용자 편집과 삭제 상태 보존 |

문서의 수치는 카테고리별 `details` JSON으로 저장합니다. SQLite에서 JSON 문자열로 보관하며 UI에서 항목명과 하위 수치를 해석합니다. 관계·출처·퀘스트·강화는 별도 테이블입니다. `content_type`은 `base_game` / `shadow_of_the_erdtree`만 사용하고, API 검증과 SQLite INSERT/UPDATE 트리거가 다른 값을 거부합니다.

관계 참조는 외래키로 검증합니다. 퀘스트 단계의 위치/NPC/필요 아이템 ID는 API에서 존재 여부를 검사하고, 참조 중인 문서의 삭제를 막습니다. 단계의 다음 ID도 같은 퀘스트에 존재해야 합니다. 퀘스트 문서 삭제 시 소속 단계는 함께 삭제합니다.

### 개인 진행 저장

- `elden-ring-archive:v1`: 즐겨찾기, 완료 ID, 스포일러 토글, 문서별 메모
- `elden-ring-builds:v1`: 빌드 목록

이는 브라우저 LocalStorage입니다. 다른 PC·브라우저·포트와 자동 동기화되지 않습니다. 시크릿 창 종료·브라우저 데이터 삭제 시 사라질 수 있으므로 체크리스트의 **진행 내보내기**로 백업하세요. 진행 데이터 가져오기는 현재 진행 기록을 대체합니다. 빌드는 별도로 내보냅니다.

DB 백업은 **서버 종료 후** `prisma/archive.db`를 복사하면 됩니다. 나중에 같은 위치로 복원하세요. SQLite가 WAL 파일을 사용하는 설정으로 바뀌었다면 DB 파일만 열려 있는 상태로 복사하지 말고 SQLite backup 기능을 사용하세요.

## 데이터 추가·수정

일상적인 수정은 `/admin`에서 수행합니다. JSON의 `relations`에 `{ "toId": "locations-gael-tunnel", "label": "획득 장소" }`처럼 연결하면 대상 문서에도 역방향 링크가 나타납니다. 검증 전 수치는 생략하고 출처 메모에 조사할 항목을 기록하세요.

새 기본 자료는 `data/base-game/curated.json` 또는 `data/shadow-of-the-erdtree/curated.json`에 추가한 뒤 검증 및 시드를 실행할 수 있습니다. **기존 DB 문서는 시드가 덮어쓰지 않습니다.** 파일에서 기존 수치를 바꾼 경우 관리자에서 해당 문서 JSON을 가져와 명시적으로 저장하세요. 삭제된 기본 문서도 시드로 되살리지 않습니다.

```bash
npm run data:collect   # 12개의 고정 공개 JSON만 순차 요청; DB 직접 변경 없음
npm run data:validate  # 필드·게임 범위·연결 검증 및 수집 통계
npm run db:seed        # 아직 입력되지 않은 새 ID만 추가
```

수집 스크립트는 HTTPS 프록시가 설정되어 있으면 공식 `undici` EnvHttpProxyAgent로 사용합니다. 프록시 인증 값은 출력하지 않습니다. 원본 응답의 SHA-256과 수집 시각은 `data/collection-report.json`에 남깁니다. 실제 출처가 바뀌거나 새 게임 자료가 혼입될 수 있는 자동 최신화를 하지 않고, 검토한 고정 커밋만 요청합니다.

수집·관리자 입력은 이름, 별칭, JSON 키/값, 관계명, 출처 URL·메모에서 `Nightreign`, `ELDEN RING NIGHTREIGN`, `밤의 통치자` 및 대소문자/전각/일부 구분자 변형을 검사합니다. 확인된 전용 이름도 거부합니다. 수집 단계의 거부 자료는 Git 제외된 `data/quarantine/`에 검토용으로 격리하고 **DB에는 저장하지 않습니다**. 본편과 공통으로 등장하는 트리 가드·밤 기병·Royal Revenant 등은 허용합니다. 문자열 검사만으로 모든 미지의 전용 콘텐츠를 판별할 수 없으므로 신규 출처의 게임 범위를 사람이 확인해야 합니다.

- 퀘스트별 아이템 선행 조건·선택 결과·정확한 실패 분기: 현재 단계의 일부는 일반적인 주의사항이며 모든 실패 조건을 표현하지 못합니다.
- 지도 원본·실제 좌표·인터랙티브 마커: 메뉴/카테고리만 있고 지도 기능은 미구현
- 지도 조각·그림·황금 종자·성배의 물방울의 장소별 독립 체크 대상
- 여러 캐릭터·회차 슬롯, NG+ 수치, 장비 비교, 보스 약점 필터, 공식 계산식 기반 공격력 계산

빌드 도우미는 저장 노트입니다. 직업별 초기 스탯·레벨 합·요구 스탯·중량·공격력을 자동 계산하지 않습니다. 탈리스만 4개 제한과 입력 범위만 검증합니다. 데이터가 부족한 카테고리는 빈 목록을 표시하며 관리자에서 추가할 수 있습니다.

## 검증

```bash
npm run data:validate
npm run typecheck
npm test
npm run build
```

브라우저 테스트:

```bash
npx playwright install chromium
npm run test:e2e
```

클라우드처럼 시스템 Chromium이 있는 경우:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

데이터 검증 단위 테스트 10개와 실제 Chromium 기능 테스트 6개를 실행했습니다. 기능 테스트는 한/영 검색·자동완성·DLC 필터·관계, 즐겨찾기/체크/메모의 새로고침 후 유지, 스포일러/퀘스트, 관리자 CRUD 및 범위 거부, 모바일 메뉴/가로 넘침, 빌드 저장을 확인합니다. SQLite 외래키 위반 0건이며 `npm install` 재실행 시 신규 입력 0개, 총 문서 수 유지도 확인했습니다.

설치·시작 지침은 클라우드 환경 설정 초안에 별도로 저장합니다. 초안 저장은 환경 게시나 새 작업에서의 복원 검증을 뜻하지 않습니다. 로컬 실행에는 해당 클라우드 설정이 필요 없습니다.
